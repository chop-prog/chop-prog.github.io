Case study: one bug, start to finish

How a vague report becomes a root cause, a fix and a test that keeps it fixed. Both issues below are real and came from playtests of VOID PULSE co-op.

  1. Symptom

    Joining a friend by link looped on “could not connect”, and joining by code took a very long time.

  2. Reproduce

    Two machines, a network that blocks direct peer-to-peer traffic, and logs of every signalling step on both sides.

  3. Root cause

    Two at once: the free signalling server was not delivering messages, and the friend's browser served an old cached build that spoke a different protocol.

  4. Fix

    Encrypted signalling over three public MQTT brokers with a relay fallback, a network-first service worker, a protocol version check in the handshake and the build number in the lobby.

  5. Keep it fixed

    Tests run co-op over a simulated network with latency, jitter and blocked peer-to-peer. Connecting now takes about 2.5 s directly and about 9 s through the relay.

Bug reportFixed in build 7

The second player's screen stutters in online co-op

Environment
Chrome on two PCs, direct WebRTC link
Severity
Major: co-op is barely playable for the guest
Steps
1. The host opens a room, the guest joins by link. 2. Start a run and kill several enemies in a row. 3. Watch the enemies on the guest's screen.
Expected
Enemies move smoothly, as they do for the host.
Actual
On the guest's screen enemies freeze for several frames, then jump ahead.
Cause
The guest's playback followed game time, which the host slows down for a moment on every kill.
Fix
Snapshots carry a steady clock; the guest plays at real speed and corrects drift by up to 15%. A test checks the pace stays within 0.8–1.2× on a jittery network.

Engineering notes

A few decisions from these projects, with the code behind them.

Tandem · crdt.ts

Merging without a server

Every field of every shape is its own register, stamped with a Lamport clock and the replica id. Merging keeps the larger stamp in a total order, so it is commutative, associative and idempotent: replicas agree however the ops arrive.

const cur = shape.get(op.key);
if (!cur || compareStamps(op.s, cur.s) > 0) {
  shape.set(op.key, { value: op.value, s: op.s });
}
// compareStamps: Lamport counter first, replica id breaks ties

Seismic · engine.ts

Crossfilter in one pass

Each event gets a bitmask of the filters it fails. Zero means selected. Exactly one bit means it still counts toward that dimension's own histogram, which is how a brushed chart keeps showing the bars outside its selection.

if (fail === 0) { selected++; /* +1 in every histogram */ }
else if (fail === T) hist.time[bt[i]]++;
else if (fail === M) hist.mag[bm[i]]++;
else if (fail === D) hist.depth[bd[i]]++;

Relay · web/sw.ts

One backend, two runtimes

The Hono app depends only on interfaces. Node runs it with SQLite; the GitHub Pages demo runs the same code in a Service Worker with an in-memory store, so the public demo goes through the real validation, auth and SSE paths.

const app = createApp({ store, signer, runtime: 'service-worker' });

self.addEventListener('fetch', (e) => {
  if (!isApiRequest(e.request)) return;
  e.respondWith(app.fetch(toAppRequest(e.request)));
});

Facet UI · contrast-sweep.mjs

Contrast checked, not assumed

jsdom can't compute colour, so CI serves the docs, steps through 2 modes × 24 accent hues in headless Chrome and runs axe on each. The first run caught two real WCAG failures, both fixed in the theme.

for (const mode of ['light', 'dark'])
  for (let hue = 0; hue < 360; hue += 15) {
    await setTheme(page, mode, hue);
    failures.push(...await axeContrast(page));
  }

Aurora · shaders.js

Navier–Stokes in a few shader passes

Each frame advects, adds vorticity confinement, solves pressure with Jacobi iterations and projects the velocity field to make it divergence-free, all in fragment shaders on half-float textures.

// one Jacobi iteration of ∇²p = ∇·u
float L = texture(uPressure, vL).x;  // …R, T, B
float div = texture(uDivergence, vUv).x;
fragColor = vec4((L + R + B + T - div) * 0.25, 0, 0, 1);

VOID PULSE · particles.js

Thousands of sparks, a few draw calls

Particles live in typed arrays with swap-remove. At draw time they are counting-sorted into colour × alpha buckets, so the whole system costs one stroke() call per bucket.

for (i = 0; i < n; i++) counts[keys[i] = bucketOf(i)]++;
prefixSum(counts);
for (i = 0; i < n; i++) order[counts[keys[i]]++] = i;
// draw: beginPath() / stroke() only when the bucket changes

How I work

I care about the parts of an interface users feel without noticing: responses that don't lag, keyboard shortcuts that just work, motion that helps instead of distracting, and states that never lose your work.

I like knowing how things work under the hood, so these projects implement their own physics, shaders and sync engines instead of hiding them behind libraries. I also know when a good library is the right call: Flowboard uses React and dnd-kit for exactly that reason.

Every project here has automated tests, a README that explains the decisions, and a CI pipeline that deploys on every push.

I build with AI assistants, mainly Claude Code. I write the task and what “done” means, read and review the code it produces, test it in the browser and with automated tests, and send it back until it is right. The AI speeds up the typing; deciding what to build and proving that it works is my part.
